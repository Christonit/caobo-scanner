# Project Plan: Smart Accounting Desktop Agent
**Architecture:** Electron + Nuxt.js (SPA) + Python (FastAPI)

## 1. Executive Summary
This project aims to build a desktop application that automates the extraction of data from scanned receipts/invoices. 
* **Frontend:** A modern Nuxt.js interface for file selection and status tracking.
* **Backend:** A local Python API that handles "heavy lifting" (AI processing and Excel manipulation).
* **Distribution:** Wrapped in Electron to create a single installable `.exe` file that runs offline.

---

## 2. Architecture Overview

### The "Sidecar" Pattern
Instead of compiling Python directly into JavaScript, we run two separate processes that talk to each other via HTTP.

1.  **Electron (The Shell):** Launches the application window and manages the lifecycle (startup/shutdown) of the Python background process.
2.  **Nuxt.js (The UI):** Runs inside the Electron window. It acts as the dashboard where the user drags and drops files.
3.  **Python FastAPI (The Engine):** Runs invisibly in the background. It listens on `localhost` (e.g., port 8000) and executes the actual logic (Gemini API calls, Excel writing).

## 3. Detailed Step-by-Step Implementation

### Phase 1: Project Initialization & Structure
**Goal:** Create a clean workspace that separates UI code from Backend code.

1.  **Initialize Nuxt:**
    * Create a standard Nuxt project.
    * **Crucial Config:** Set `ssr: false` in `nuxt.config.ts`. This forces Single Page Application (SPA) mode, which is required for Electron.
2.  **Folder Structure:**
    * Create a root folder.
    * Inside, keep the standard Nuxt folders (`pages`, `components`).
    * Create a dedicated directory named `python_backend` for your API scripts.
    * Create a directory named `electron` for the main process scripts.
3.  **Install JavaScript Dependencies:**
    * Add `electron` and `electron-builder` to your `package.json` dev dependencies.
    * Add `concurrently` (optional but recommended) to run both Nuxt and Electron with one command during development.

### Phase 2: The Python Backend ("The Brain")
**Goal:** Build a local API that accepts images and returns data, independent of the UI.

1.  **Environment Setup:**
    * Set up a Python virtual environment inside `python_backend`.
    * Install: `fastapi`, `uvicorn` (server), `google-generativeai` (Gemini), `openpyxl` (Excel), `pandas`, and `python-multipart` (for file uploads).
2.  **Implement Logic - Duplicate Detection:**
    * Create a function that calculates the **MD5 Hash** of an incoming file.
    * Maintain a local `history.json` file.
    * **Logic:** Before processing, check if the hash exists in `history.json`. If yes, reject the request immediately with a "Duplicate" status.
3.  **Implement Logic - AI Processing (Gemini):**
    * Initialize the Gemini client with your API key.
    * Create a System Prompt: *"You are a data extraction assistant. Extract Date, Vendor, Total, and Tax. Return valid JSON only."*
    * Pass the image file buffer to Gemini Vision.
4.  **Implement Logic - Excel Manipulation:**
    * Use `openpyxl` to load your master `.xlsx` template.
    * Find the first empty row.
    * Map the JSON data from Gemini to the specific columns (A, B, C, etc.).
    * Save the file. *Note: Ensure the file isn't open by the user, or handle the "Permission Denied" error gracefully.*
5.  **Create API Endpoints:**
    * `POST /upload`: Accepts a file. Runs Hash Check -> AI -> Excel Write. Returns the extracted data.
    * `GET /download`: Copies the modified Excel file from the temp working directory to the user's "Downloads" or "Desktop" folder.

### Phase 3: The Electron "Glue"
**Goal:** Make the app feel like a native desktop program.

1.  **Background Process Management:**
    * In the Electron `main.js`, use Node.js `child_process` to spawn the Python server when the app launches.
    * **Important:** Store the process ID (PID).
    * Add a listener to the `app.quit` event to kill the Python process. If you skip this, the Python server will keep running in the background forever (memory leak).
2.  **Development vs. Production Modes:**
    * **Dev Mode:** Electron should load `http://localhost:3000` (your Nuxt HMR server).
    * **Prod Mode:** Electron should load the `index.html` file generated by `nuxt generate`.

### Phase 4: Frontend Development (Nuxt/Vue)
**Goal:** Build the user interface.

1.  **State Management (Pinia/Ref):**
    * Create a state object to hold a list of files.
    * Structure: `{ id: 1, name: 'receipt.jpg', status: 'pending' | 'processing' | 'done' | 'duplicate', data: {} }`.
2.  **File Selection Component:**
    * Create a drag-and-drop zone or a file input button (`<input type="file" multiple>`).
    * On selection, populate the state list (do not upload yet).
3.  **The Processing Queue (The Loop):**
    * Create a `processAll()` function.
    * **Iterate:** Loop through the file list.
    * **Async/Await:** Send one file to the Python `POST /upload` endpoint. Wait for the response before sending the next one (to avoid hitting Gemini rate limits).
    * **Update UI:** As each response comes back, update the status icon and display extracted data in a table row.
4.  **Download/Finish:**
    * Show a "Export Completed Excel" button that calls the `GET /download` endpoint.

### Phase 5: Packaging & Distribution
**Goal:** Create the single `.exe` file.

1.  **Compile Python:**
    * Use `PyInstaller` to compile your `server.py` into a single file: `backend.exe`.
    * Command flag `--noconsole` ensures no black command window pops up.
2.  **Build Nuxt:**
    * Run `nuxt generate`. This creates a `dist` (or `.output`) folder with static HTML/JS.
3.  **Configure Electron Builder:**
    * Edit `package.json` configuration.
    * **Resources:** Tell it to copy `backend.exe` and your Excel template into the final app package (`extraResources`).
    * **Files:** Tell it to use the Nuxt `dist` folder as the app's source code.
4.  **Final Build:**
    * Run the build command. You will receive a `Setup.exe` in your output folder.

## 4. Technical Workflows

### How Hot Module Reload (HMR) Works
You will use two terminal windows during development:
1.  **Terminal A:** Runs `nuxt dev`. This starts the standard web server with HMR.
2.  **Terminal B:** Runs `electron .` (configured to point to localhost:3000).
*Result:* You can edit Vue files, save them, and the Electron window updates instantly without restarting.

### How Duplicate Detection Works (Hashing)
1.  User selects `Starbucks_001.jpg`.
2.  Python reads the file bytes and calculates an MD5 hash (e.g., `a1b2c3d4...`).
3.  Python looks up `a1b2c3d4...` in `processed.json`.
4.  **Scenario A (Found):** Python returns JSON `{"status": "duplicate"}`. Nuxt marks the row as skipped.
5.  **Scenario B (New):** Python processes the file, adds data to Excel, and appends `a1b2c3d4...` to `processed.json`.

### How File Paths Work
* **In Dev:** Python runs from your code folder.
* **In Prod:** Python runs from a locked "Program Files" directory.
* *Solution:* In your Python code, dynamically detect the "current working directory" using `sys._MEIPASS` (a special PyInstaller variable) to ensure it can always find your Excel template, regardless of where the app is installed.
